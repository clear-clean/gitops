## Repository Purpose

This is a GitOps repository managing Kubernetes cluster configuration using **Flux CD v2.7.5**. Flux runs inside the cluster and continuously reconciles the desired state declared here against the actual cluster state.

## Architecture

The repo follows the Flux multi-cluster convention:

```
clusters/
  cluster/
    flux-system/        # Flux bootstrap manifests (auto-generated, do not hand-edit)
```

- **`gotk-components.yaml`** — Auto-generated Flux component manifests (source-controller, kustomize-controller, helm-controller, notification-controller, image-reflector-controller, image-automation-controller). Regenerated by `flux install --export`.
- **`gotk-sync.yaml`** — Defines the `GitRepository` (SSH, 1m interval) and root `Kustomization` (10m interval) that tell Flux to watch this repo at path `./clusters/cluster`.
- **`kustomization.yaml`** — Kustomize resource list tying the above together.

## Key Conventions

- Application manifests and Helm releases should be added under `clusters/cluster/` (or subdirectories referenced via Kustomizations).
- The repo is synced via SSH (`ssh://git@github.com/clear-clean/gitops`). The cluster holds the deploy key secret in `flux-system/flux-system`.
- Do **not** hand-edit `gotk-components.yaml` — it is marked as auto-generated. To upgrade Flux, use `flux install --export > clusters/cluster/flux-system/gotk-components.yaml`.

## Useful Flux CLI Commands

```bash
# Check Flux prerequisites on a cluster
flux check --pre

# Bootstrap or reinstall Flux (writes gotk-components.yaml)
flux install --export > clusters/cluster/flux-system/gotk-components.yaml

# Force reconciliation
flux reconcile source git flux-system
flux reconcile kustomization flux-system

# View sync status
flux get all
```
